# Quantum Resonator

An audio-reactive, iridescent 3D artifact rendered in the browser with Three.js. A thin-film interference shader wraps a rotating mesh in shifting spectral color, and the surface vibrates, shifts hue and glows in time with music, your microphone, or a built-in synthesized beat.

Optionally, the material can be replaced by a **quantum-synthesized BSDF** generated by Moth Atlas's `entanglement-shader-v1` engine.

## Features

- **Thin-film iridescence**: a custom GLSL shader that approximates light interference in a nanometer-scale film, so the color changes with viewing angle, film thickness and position on the surface.
- **Audio reactivity** from three sources:
  - ▶ **Play Beat**: a 120 BPM kick / snare / hat / bassline synthesized live with the Web Audio API (no audio files)
  - 🎤 **Mic**: live microphone input
  - 📂 **Load Audio**: any local audio file
- **Quantum BSDF synthesis**: sends material parameters to the Moth Atlas API and hot-swaps the returned GLSL shader and lookup textures onto the mesh.
- **5 geometries**: Torus Knot (3,5), Torus Knot (2,3), Quantum Icosahedron, Geodesic Sphere, Klein Torus.
- **Studio rendering**: ACES tone mapping, image-based lighting, 3-point lights, bloom, and a starfield backdrop.
- **1-click recording**: captures a 15-second `.webm` clip of the canvas with audio.

## Getting started

Requires [Node.js](https://nodejs.org/) 18+.

```bash
git clone https://github.com/VedantMahadik-qc/quantum-resonator.git
cd quantum-resonator
npm install
npm run dev
```

Then open the URL Vite prints (usually http://localhost:5173).

| Command           | What it does                              |
| ----------------- | ----------------------------------------- |
| `npm run dev`     | Start the dev server with hot reload      |
| `npm run build`   | Build a production bundle into `dist/`    |
| `npm run preview` | Serve the production build locally        |

## How it works

### Rendering pipeline (`src/scene.js`)

```
Mesh + ShaderMaterial ──► RenderPass ──► UnrealBloomPass ──► OutputPass ──► screen
```

The scene sets up the camera, orbit controls (drag to rotate, scroll to zoom), lighting, the post-processing chain and the animation loop. On every frame it reads the latest audio levels, smooths them, and writes them into the shader uniforms.

### The iridescent shader (`src/iridescentShader.js`)

This is the default material. It works with no network access at all.

- **Vertex stage**: pushes each vertex along its normal by `bass × sin(y·8 + t·6)`, so the surface ripples with the low end.
- **Fragment stage**: models thin-film interference. For each pixel it computes an optical path length `2 · n · d · cos θ` (index of refraction `n`, film thickness `d` in nm, view angle `θ`) and compares it against red, green and blue wavelengths (650 / 550 / 450 nm). The phase difference sets each channel's brightness, which gives the soap-bubble / oil-slick banding. A spatial phase term keeps the colors moving across flat faces instead of only at the silhouette. Two specular highlights and a Fresnel rim glow sit on top.

The dock sliders map directly to uniforms:

| Slider          | Uniform         | Effect                                                     |
| --------------- | --------------- | ---------------------------------------------------------- |
| Reflectance     | `uReflectance`  | Index of refraction, film thickness and Fresnel sharpness  |
| Absorption      | `uAbsorption`   | Darkens the base surface color                             |
| Interaction     | `uInteraction`  | Phase offset that rotates the interference hues            |

### Audio analysis (`src/audioEngine.js`)

All three inputs feed a single Web Audio `AnalyserNode` (FFT size 512). Every frame the spectrum is reduced to four values between 0 and 1:

| Band    | Range        | Drives                                                   |
| ------- | ------------ | -------------------------------------------------------- |
| Bass    | 20–250 Hz    | Vertex displacement, film thickness (+350 nm), bloom     |
| Mid     | 250–4000 Hz  | Interference phase shift (hue rotation)                  |
| Treble  | 4–16 kHz     | Level meter                                              |
| Energy  | RMS of wave  | Level meter                                              |

Higher bands get more gain because they carry less energy in typical music. The **Sensitivity** slider scales all four. The scene then applies frame-rate-independent exponential smoothing, so the visuals pulse instead of flickering.

The microphone goes only to the analyser and is never played through the speakers, which avoids feedback. The beat and loaded files are also routed to a `MediaStreamDestination` so the recorder can include their audio in the clip.

### Quantum BSDF synthesis (`src/mothShader.js`, `src/mothShaderAdapter.js`)

When you enter a Moth Atlas API key and click **Synthesize Quantum BSDF**:

1. The parameters (reflectance, absorption, layers, incoming rays, style, interaction) are submitted as a job to `entanglement-shader-v1`.
2. The app polls the job until it completes (2-minute timeout).
3. It downloads the result `.zip` and extracts `entanglement_texture.glsl` plus the optional `R_lut.hdr` / `T_lut.hdr` reflectance and transmittance lookup textures.
4. **The adapter** rewrites the returned GLSL so it compiles in WebGL. It strips `#version` and precision directives, converts `in` to `varying` and `texture()` to `texture2D()`, and turns multiple render-target outputs into locals. If the shader outputs reflectance and transmittance, they're combined with a Cook-Torrance GGX microfacet BRDF (with Smith shadowing, so the edges don't blow out to white). If the shader has no `main()`, the adapter finds its entry function and guesses its arguments from the parameter names.
5. The material is test-compiled against the live WebGL context before it's swapped in.

If any step fails, the status badge shows an error and the scene falls back to the built-in iridescent shader, so the app always renders something.

> **Note:** API calls go through Vite's dev-server proxy (`/moth-api` → `api.mothquantum.com`), and there's a `/download-proxy` fallback for CORS-restricted download URLs. Both exist only under `npm run dev`. A static deploy (e.g. GitHub Pages) still renders the default shader and all the audio features, but synthesis needs a proxy of your own.
>
> Your API key is stored only in your browser's `localStorage`. It's never written to the repo.

### Recording (`src/recorder.js`)

**Record 15s Clip** turns on auto-rotate, starts the demo beat if nothing is playing, and captures the canvas at 60 fps (12 Mbps VP9/VP8) together with the audio track using `MediaRecorder`. When the clip ends it downloads automatically as `quantum-resonator-showcase.webm`.

## Project structure

```
├── index.html               # UI layout: top bar, audio dock, material dock
├── vite.config.js           # Dev proxies for the Moth Atlas API + build settings
└── src/
    ├── main.js              # Wires the UI controls to the scene, audio and API
    ├── scene.js             # Three.js scene, geometries, render loop, shader swapping
    ├── iridescentShader.js  # Default thin-film GLSL shader
    ├── audioEngine.js       # Web Audio: beat synth, mic, file, frequency bands
    ├── mothShader.js        # Moth Atlas job submission, polling, zip/HDR parsing
    ├── mothShaderAdapter.js # Rewrites returned GLSL into WebGL-compatible form
    ├── recorder.js          # Canvas + audio → .webm recorder
    └── style.css            # UI styling
```

## Tech stack

[Three.js](https://threejs.org/) · [Vite](https://vitejs.dev/) · Web Audio API · MediaRecorder API · [JSZip](https://stuk.github.io/jszip/)

## Browser support

Works best in recent Chrome, Edge or Firefox. You need WebGL for rendering; the microphone and recording features also need the browser to allow mic access and `MediaRecorder` with WebM. Safari's WebM recording support is limited.
